## Mentor-Revealed Requirements (from explainer slides)

The slides made explicit what the PDF only hinted at:

1. **Independent detector pipelines** — Milestone 1 says SoLEXS and HEL1OS detection must be 
   built independently, then fused into a unified master catalog (Milestone 2). NOT a joint 
   black-box model.
2. **QPP detection** — Quasi-Periodic Pulsations explicitly named on slides. Wavelet-based 
   detection of 1s–5min oscillations in hard X-ray during flares. This is the differentiator 
   almost no team will think to do.
3. **Pre-flare precursor detection** — Slide 4 shows "Precursor Heating Detected" in red 
   before the actual peak. Forecasting target is detection of soft X-ray gradient + hard X-ray 
   emergence in 5–30 min window before impulsive phase.
4. **15-minute forecast horizon** — explicitly shown in their example.
5. **Multi-class B/C/M/X probabilities** — required, not optional.
6. **Visual dashboard** — Slide 1 mock shows solar disk view + risk gauge + multi-band 
   light curves + alert log. Match this design language.

## Architecture (5 phases)

```
Phase 1: Unified Light Curves
  Raw FITS (SoLEXS + HEL1OS) → daily Parquet on common UTC grid

Phase 2: Labeled Dataset
  Daily Parquet + flare catalog → per-second labels 
  (is_flare, flare_class, time_to_peak, phase, precursor_window_30min)

Phase 3: Nowcasting
  5 independent detection pipelines:
    - SoLEXS-SDD2
    - HEL1OS-CdTe1, HEL1OS-CdTe2
    - HEL1OS-CZT1, HEL1OS-CZT2
  Each produces its own flare catalog.
  Fusion layer produces Master Flare Catalog.
  Separate QPP detection module (wavelet-based) on HEL1OS hard X-ray.

Phase 4: Forecasting
  Feature engineering on labeled dataset:
    - Soft X-ray gradient (d/dt of GOES-equivalent band)
    - Hardness ratio evolution (HEL1OS/SoLEXS)
    - Hard X-ray background-subtracted rate
    - Time since last flare
    - F10.7, sunspot number, active region count covariates
    - QPP presence flag in trailing window
  Model: Temporal Fusion Transformer (TFT) with quantile outputs.
  Multi-class heads for B/C/M/X.
  Calibration via isotonic regression.

Phase 5: Dashboard + Serving
  FastAPI inference service.
  Streamlit dashboard: light curves + risk gauge + alert log + flare catalog browser.
  Live demo capability.
```

## Data Schema Reference

### HEL1OS zip structure
```
HLS_YYYYMMDD_HHMMSS_DDDDDsec_lev1_VXYZ.zip
└── HLS_.../ 
    ├── events/evt.fits           (4 HDUs: CDTE1-EVENTS, CDTE2-EVENTS, CZT1-EVENTS, CZT2-EVENTS)
    │                              Columns: mjd, hlsobt, currtemp, chn, ener, recnum, utc-isot
    │                              (CZT adds: pix, offsetchn)
    ├── cdte/
    │   ├── lightcurve_cdte1.fits  (5 HDUs, one per energy band)
    │   ├── lightcurve_cdte2.fits
    │   ├── hel1os_cdte_spectra_cdte1.fits  (SPECTRUM HDU, 511 channels, 20s binning)
    │   └── hel1os_cdte_spectra_cdte2.fits
    ├── czt/
    │   ├── lightcurve_czt1.fits
    │   ├── lightcurve_czt2.fits
    │   ├── hel1os_czt_spectra_czt1.fits  (341 channels)
    │   └── hel1os_czt_spectra_czt2.fits
    └── aux/
        ├── gticdte1.fits, gticdte2.fits, gticzt1.fits, gticzt2.fits
        └── hk.fits

HEL1OS Light Curve Bands:
  CdTe: 5-20, 20-30, 30-40, 40-60, 1.8-90 keV
  CZT:  20-40, 40-60, 60-80, 80-150, 18-160 keV

HEL1OS Light Curve Columns: MJD, ISOT, CTR (cts/sec), STAT_ERR
HEL1OS GTI HDU name: GTI_CDTE1 / GTI_CDTE2 / GTI_CZT1 / GTI_CZT2
HEL1OS GTI Columns: tstart, tstop (in MJD days)
HEL1OS Time: utc-isot column already populated; mjd column gives MJD.
```

### SoLEXS zip structure
```
AL1_SLX_L1_YYYYMMDD_v1.0.zip
└── AL1_SLX_L1_YYYYMMDD_v1.0/
    ├── SDD1/  (empty — only contains an empty GTI file; SKIP)
    └── SDD2/
        ├── AL1_SOLEXS_YYYYMMDD_SDD2_L1.gti.gz   (GTI HDU, START/STOP in Unix epoch)
        ├── AL1_SOLEXS_YYYYMMDD_SDD2_L1.lc.gz    (RATE HDU; columns: TIME, COUNTS)
        └── AL1_SOLEXS_YYYYMMDD_SDD2_L1.pi.gz    (SPECTRUM HDU, 340 channels, 1s binning)

SoLEXS Time: TIME column is Unix epoch seconds, TIMESYS=UTC, MJDREFI=40587.
```

### Versioning
HEL1OS observations have version codes (V111, V112, V211, V311 etc.).
134 timestamps have multiple versions. The loader picks the highest version per timestamp.

## Strategic Differentiators

What separates a winning submission from a competent one:

1. **Independent 5-detector architecture** (not joint black-box) — matches Milestone 1 exactly
2. **QPP detection module** — almost no other team will do this; novel scientific contribution
3. **Neupert-effect-aware features** in the forecaster (hard X-rays as derivative of soft)
4. **Calibrated uncertainty** in forecasts (quantile outputs, not single-point probabilities)
5. **Pre-finale draft research note** signaling publication intent
6. **Open-source Python package** (`aditya-flare`) for community use
